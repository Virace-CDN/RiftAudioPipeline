# RiftAudioPipeline 下一步操作文档

## 1. 目的

在会话上下文可能中断的情况下，固化当前实现认知与下一步执行顺序，确保后续可无缝续做。

## 2. 当前已确认逻辑（截至 2026-03-04）

### 2.1 更新判定主逻辑

1. 读取最新版本（GAME/LCU）与本地状态文件 `state/run_history.json`。
2. 首次执行（无本地状态）：
   - 直接进入更新流程。
3. 非首次执行：
   - 若 GAME 版本号完全相同：跳过更新。
   - 若 GAME 版本变化：对比旧新 manifest，得到 `added/changed/removed` 的 WAD 路径。
4. 对 `update_paths` 继续做二次筛选（基于 BIN 解析出的 VO 资源路径）：
   - 仅 `*_vo_audio.bnk` / `*_vo_audio.wpk` 变化触发解包。
   - 仅 `*_vo_events.bnk` 变化不触发资源解包。
   - 结果缓存到 `state/voice_filter_results/`。

### 2.2 解包执行链路（已跑通）

现有可用链路：
`DataUpdater -> BinUpdater -> run_unpack(或 run_unpack_by_entity)`

实测脚本：
`scripts/test_single_unit_download_unpack_live.py`

最新实测结果：
- 在清空 `temp/` 后再次运行成功。
- 产物路径：`temp/live_single_unit/output/audios/16.4/champions/...`

### 2.3 最小游戏目录能力

已具备：
- 构建最小游戏目录结构；
- 写入 `content-metadata.json`；
- 将运行时文件按相对路径落地（支持硬链接失败回退复制）。

## 3. 关键未完成项（当前阻塞闭环）

### 3.1 在线下载未接入 pipeline 主流程

虽然已实现 `asset_downloader.py`，但 `pipeline.py` 里尚未接入：
- 下载 LCU WAD 并落地到最小游戏目录；
- 按 `unpack_paths`/目标实体下载 GAME WAD 并落地。

当前 `pipeline` 仅在无 `--game-path` 时创建目录并写 metadata，未完成在线资源填充。

### 3.2 BIN 复用未打通自动落地

当前二次筛选阶段会提取 BIN 并在内存解析，但没有自动落地到 `manifest/<version>/bin_input` 供后续 `BinUpdater` 复用。

现状仅支持手动指定 `--local-bin-dir` 导入本地 bin，尚未实现“筛选阶段产物 -> 后续阶段自动复用”。

### 3.3 打包模块未实现

`src/rift_audio_pipeline/packer.py` 仍为 `NotImplementedError`，无法产出压缩包。

### 3.4 上传与清单同步未接入主流程

百度网盘 `BaiduPanClient` 已有能力，但未在 `pipeline.py` 中串联“打包产物上传 + manifest 同步”。

## 4. 下一步执行计划（按优先级）

## P0：打通“下载 + BIN 复用 + 解包”主流程

1. 在 `pipeline.py` 接入在线下载：
   - 下载 `content-metadata.json`；
   - 下载 LCU `default-assets*.wad` + `{region}-assets.wad`；
   - 按目标实体/`unpack_paths` 下载对应 GAME WAD。
2. 统一复用同一个最小游戏目录：
   - 最小游戏搭建与后续下载均落地到同一目录。
3. 实现 BIN 自动复用：
   - 将二次筛选阶段命中的 BIN 原始数据或可重用结果落地到 `bin_input`；
   - 自动创建 `.use_local_bin`；
   - 避免后续重复下载/重复解析。

验收：
- 不传 `--game-path` 的情况下，`pipeline` 可端到端执行到解包成功；
- 同一次运行中 BIN 不重复拉取。

## P1：实现打包（7-zip，支持文件名加密）

1. 在本项目 `packer.py` 实现 7z 打包：
   - 支持密码；
   - 支持 `-mhe=on`（文件名加密）；
   - 支持附加文件（说明/许可证等）。
2. 参考仓库：
   - `H:/Programming/Python/lol_audio_unpack/packer/packer.py`
   - `H:/Programming/Python/lol_audio_unpack/packer/extra/`
3. 使用现有产物做验证：
   - `temp/live_single_unit/output/audios/16.4`

验收：
- 可输出 `.7z`；
- 错误密码下无法浏览文件列表（验证文件名加密生效）；
- 压缩包内包含附加说明文件。

## P2：接入上传闭环

1. `pipeline.py` 在打包后调用百度上传；
2. 同步远端执行清单（manifest）；
3. 成功后按策略清理本地临时 WAD/中间件。

验收：
- 首次执行可全量上传；
- 增量执行仅上传变更实体产物。

---

## 5. 建议的最近一次落地顺序

1. 先完成 P0（保证“判断更新 -> 最小游戏下载搭建 -> BIN 复用 -> 解包”全自动）。
2. 再完成 P1（先本地打包验证，再接主流程）。
3. 最后完成 P2（上传与清单同步）。
